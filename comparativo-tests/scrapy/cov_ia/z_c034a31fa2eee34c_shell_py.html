38# Hopefully temporary architecture notes 

39# 

40# The Shell class is always instantiated in the "main" thread. There are two 

41# official ways to use it: 

42# 1. scrapy.commands.shell, which makes a secondary thread and calls 

43# CrawlerProcess.start() in it, which runs a reactor there. 

44# 2. scrapy.shell.inspect_response(), which just creates Shell() in the current 

45# thread. 

46# 

47# Shell._inthread is True when this class is run in a thread separate from the 

48# reactor, e.g. the 1st way (in other words, the reactor is in a secondary 

49# thread). 

50# Shell._inthread is False when this class is run in the same thread as the 

51# reactor, e.g. the 2nd way. 

52# The only thing that differs is availability of fetch() (it needs the 

53# reactor to be in a separate thread: the shell sends the request to 

54# the reactor and waits for the result synchronously). 

55# 

56# Thus the only thing Shell needs an event loop for is fetch(). More machinery 

57# is used for it to work. In chronological order: 

58# 1. scrapy.commands.shell.Command.run() creates a crawler and an engine, then 

59# calls 

60# _schedule_coro(crawler.engine.start_async(_start_request_processing=False)), 

61# which initializes the engine but doesn't start processing of requests. 

62# 2. scrapy.commands.shell.Command.run() calls crawler_process.start() in a 

63# thread which starts a reactor in that thread. 

64# 3. When fetch() is called, it prepares a request and calls Shell._schedule() 

65# in the reactor thread (via threads.blockingCallFromThread()). 

66# 4. Shell._schedule() calls Shell._open_spider() (on the first call). 

67# 5. Shell._open_spider() calls 

68# engine.open_spider_async(close_if_idle=False). 

69# 6. Shell._schedule() calls engine.crawl(request), scheduling the request. 

70# 7. Shell._schedule() via _request_deferred() waits until the request callback 

71# is called. When it's called, the response becomes available. 

72# 

73# In the reactorless mode this is slightly different, the engine initialization 

74# happens in the event loop thread as many things need either a reactor or a 

75# running event loop. 

76# 

77# Side note: it should be possible to remove _request_deferred() by using 

78# engine.download_async() instead of engine.crawl(), losing the usual stuff 

79# like spider middlewares (none of which should be important). 

80# 

81# Other architecture problems: 

82# * scrapy.cmdline.execute() creates an AsyncCrawlerProcess instance which 

83# immediately installs a reactor (which is maybe not thread-specific?) or an 

84# event loop (which *is* thread-specific, so the main thread will always have 

85# a (not running) loop installed. 

86# * scrapy.commands.shell.Command.run() calls _schedule_coro() in the main 

87# thread, and various engine init code also calls similar things, 

88# conceptually this shouldn't work (and doesn't in the reactorless mode, so 

89# there the initialization is moved to the event loop thread). 

90# * The engine has several code paths specifically for the shell, and the shell 

91# uses several private members of the engine and of AsyncCrawlerProcess.

188 async def _schedule(self, request: Request, spider: Spider | None) -> Response: 

189 """Send the request to the engine, wait for the result. 

190 

191 Runs in the reactor thread when using the reactor, or in the asyncio 

192 event loop thread otherwise. 

193 """ 

194 if not self.spider: 

195 await self._open_spider(spider) 

196 # send the request to the engine 

197 self.crawler.engine.crawl(request) 

198 # this will fire when the request callback runs (via the callback hijacking in _request_deferred()) 

199 return await maybe_deferred_to_future(_request_deferred(request))

312def _request_deferred(request: Request) -> Deferred[Any]: 

313 """Wrap a request inside a Deferred. 

314 

315 This function is harmful, do not use it until you know what you are doing. 

316 

317 This returns a Deferred whose first pair of callbacks are the request 

318 callback and errback. The Deferred also triggers when the request 

319 callback/errback is executed (i.e. when the request is downloaded) 

320 

321 WARNING: Do not call request.replace() until after the deferred is called. 

322 """ 

323 request_callback = request.callback 

324 request_errback = request.errback 

325 

326 def _restore_callbacks(result: Any) -> Any: 

327 request.callback = request_callback 

328 request.errback = request_errback 

329 return result 

330 

331 d: Deferred[Any] = Deferred() 

332 d.addBoth(_restore_callbacks) 

333 if request.callback: 

334 d.addCallback(request.callback) 

335 if request.errback: 

336 d.addErrback(request.errback) 

337 

338 request.callback, request.errback = d.callback, d.errback 

339 return d
